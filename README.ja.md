# FnCaps

[English](README.md) | [한국어](README.ko.md) | 日本語 | [简体中文](README.zh-Hans.md) | [繁體中文](README.zh-Hant.md) | [Українська](README.uk.md) | [Русский](README.ru.md) | [Français](README.fr.md) | [Español](README.es.md) | [Deutsch](README.de.md)

FnCapsは、入力ソースを3つ以上使い、その切り替えが遅いと感じる方のためのmacOS用メニューバーアプリです。

macOSには、入力ソースを1つずつ順番に切り替えるキーが1つ用意されています。入力ソースが3つ以上あると、目的の言語になるまでキーを押し、メニューバーで確認し、また押すことになります。

FnCapsは入力ソースを2つのキー、Caps Lockとfn(🌐)に分けます。

- それぞれのキーには独立したリストがあり、そのリストの中だけで切り替わります。
- どの言語をどちらのキーに置くかは自分で決めます。たとえば英語をCaps Lockに、ほかの言語をfnに置きます。
- 1つの長いリストが、2つの短いリストになります。FnCapsがおすすめする配置では、目的の言語まで1回か2回のキー操作で届くため、入力が中断されません。
- 言語が多い場合は、入力ソースに専用のショートカットを割り当てて、直接切り替えられます。
- Caps Lockは遅延なく切り替わります。長押しすると、これまでどおりCaps Lockのオン/オフになります。

> **初回起動時:** FnCapsはAppleによる公証を受けていないため、macOSにより一度ブロックされます。システム設定 > プライバシーとセキュリティを開き、「このまま開く」をクリックします。手順は[このまま開く](#open-anyway)にあります。

> FnCapsは1.0まで初期開発の段階です。

## 動作環境

- macOS 14 Sonoma以降、Apple siliconまたはIntel
- アクセシビリティの権限。FnCapsがfnとCaps Lockの押下を検知するために必要です。

## インストール

### Homebrew

```sh
brew install --cask Seo650/tap/fncaps
```

### GitHub Releases

1. [Releases](https://github.com/Seo650/FnCaps/releases/latest)から最新の`FnCaps-x.y.z.zip`をダウンロードします。
2. 解凍します。
3. `FnCaps.app`を`/Applications`に移動します。

## 初回起動

<a id="open-anyway"></a>

### このまま開く

FnCapsは独自の証明書で署名されており、Appleによる公証を受けていないため、macOSが初回起動をブロックします。これは一度だけ起こります。

1. FnCapsを開きます。macOSがアプリを検証できないと表示します。「完了」をクリックします。
2. システム設定 > プライバシーとセキュリティを開きます。
3. 「セキュリティ」で「このまま開く」をクリックします。
4. パスワードを入力するかTouch IDを使用し、「開く」をクリックします。

「このまま開く」ボタンは、ブロックされた起動のあとにだけ表示され、約1時間残ります。表示されない場合は、FnCapsをもう一度開きます。コマンドラインを使う場合は、次でブロックを解除できます:

```sh
xattr -dr com.apple.quarantine /Applications/FnCaps.app
```

### セットアップ

FnCapsを開くと、アクセシビリティの権限とキーの配置を順に案内します。FnCapsはfnとCaps Lockの押下を検知するためにこの権限を必要とします。すべての設定は、あとからFnCapsの設定で変更できます。

## アップデート

FnCapsは1日に1回、新しいバージョンがあるか確認します。インストールするには、FnCapsの設定を開き、「FnCapsについて」で「アップデート」をクリックします。「アップデート」をクリックするまで何もインストールされません。Homebrewでインストールした場合も同じ方法で更新できます。

アップデート後もアクセシビリティの権限は保持されます。すべてのリリースが同じ証明書で署名されているためです。

## FnCapsが送信する情報

FnCapsは入力した内容を記録しません。インターネットに接続するのは次の2つの場合です。

- アップデートの確認: 1日に1回、最新リリースをGitHub APIに問い合わせます。リクエストに含まれるのはアプリのバージョンだけで、あなたに関する情報は含まれません。
- 問題を報告: 「送信」をクリックするまで何も送信されません。報告には、入力したメッセージ、入力した場合のメールアドレス、アプリとmacOSのバージョン、Macの機種、キーボードの種類、FnCapsの設定、入力ソース、最近の動作記録、および1日の上限にだけ使われるランダムなインストール番号が含まれます。入力した内容、シリアル番号、その他のデバイスIDは含まれません。送信前にすべての内容を確認できます。報告は、開発者だけが読める非公開のリポジトリに保存されます。
- 報告の上限: インストールごとに1日5件、1つのネットワークアドレスからは1分間に5件です。

## 既知の制限

- パスワード欄: macOSはパスワード欄を英語のまま扱うため、FnCapsはそこで言語を切り替えません。また、Caps Lockを長押ししてもCaps Lockはオンになりません。
- Control+Space: FnCapsがオンの間は入力ソースを切り替えません。FnCapsをオフにするか終了すると、再び動作します。
- Caps Lockランプ: キーを長押ししてCaps Lockをオンにすると、キーのランプは点灯しません。大文字は通常どおり入力されます。
- 言語インジケータ: キーをすばやく押すと、カーソルの横にmacOSが表示する小さなインジケータが、実際に使用中の言語と異なる言語を示すことがあります。メニューバーには正しい言語が表示されます。
- 変換中の文字: fnを押したときに、韓国語、日本語、中国語の文字がまだ変換中だと、その文字が失われることがあります。
- 英語の配列: FnCapsはABCとU.S.を英語として扱います。ABC – AZERTYとABC – QWERTZはフランス語とドイツ語として扱います。
- Karabiner-Elementsとgksdud: これらのアプリは同じキーを変更します。`caps_lock`を使うKarabinerのルールがあると、FnCapsがキーを認識する前にそのルールがキーを取得します。どちらかが動作している間は、FnCapsが警告を表示します。
- 未検証(動作する見込み): 外付けキーボードの抜き差し、macOS 14から26、Apple siliconのMacBook Air以外のMac。

## 復元

Caps Lockが動作しなくなった場合:

- FnCapsで、メニューバーのアイコンから「キーを復元」を選択するか、設定 > 一般の「元に戻す」をクリックします。これにより、Caps Lockと入力ソースのショートカットがFnCapsを使う前の状態に戻ります。
- FnCapsが動作していない場合(クラッシュした後など)は、Caps Lockの再マップが残り、何も動作しないことがあります。ターミナルで再マップを解除してから、FnCapsをもう一度開きます:

  ```sh
  hidutil property --set '{"UserKeyMapping":[]}'
  ```

- このリポジトリをクローンした場合は、次のスクリプトで再マップを解除し、入力ソースのショートカットも復元できます:

  ```sh
  scripts/caps-recover.sh --restore
  ```

FnCapsを終了してもControl+Spaceで入力ソースが切り替わらない場合は、システム設定 > キーボード > キーボードショートカット > 入力ソース >「前の入力ソースを選択」を確認します。「キーを復元」はこれをFnCapsを使う前の状態に戻します。

## アンインストール

先にFnCapsを終了します。終了すると、Caps Lockと入力ソースのショートカットが元の状態に戻ります。そのあと次を実行します:

```sh
brew uninstall --cask fncaps
```

または、`FnCaps.app`を`/Applications`からゴミ箱に移動します。設定も削除する場合は、`brew uninstall --zap --cask fncaps`を使います。

## ソースからビルド

```sh
swift build
scripts/build-app.sh
```

`scripts/build-app.sh`は`build/FnCaps.app`を作成します。「FnCaps Dev Local」証明書がある場合はそれで署名し、ない場合はアドホック署名で署名します。アドホック署名の場合、ビルドのたびにmacOSがアクセシビリティの権限を再度求めます。`scripts/make-local-identity.sh`はローカル証明書を作成します。
